Memory Bank Controllers

Extending the emulator beyond 32KB to run real-world Game Boy games

Why MBCs Are Needed

Up to this point, the emulator could successfully run games like Tetris because Tetris fits entirely within 32KB — the maximum ROM space the Game Boy CPU can directly address. The Game Boy's memory map dedicates addresses $0000–$7FFF to ROM: the first 16KB ($0000–$3FFF) are permanently mapped to ROM bank 0, and the second 16KB ($4000–$7FFF) are available for a switchable ROM bank. With no switching logic, that upper window always reads from physical ROM addresses $4000–$7FFF — perfectly sufficient for a 32KB cartridge.

Most commercial games exceed 32KB. Pokémon Blue, for example, is 512KB — sixteen times larger. There is simply no way to map that much data into 32KB of address space at once. The solution used by Nintendo and third-party developers was to put an extra chip on the cartridge itself: the Memory Bank Controller (MBC). This chip intercepts writes to the ROM area (which would otherwise be ignored on a read-only chip) and uses them as control registers, swapping different physical ROM banks into the CPU's view of $4000–$7FFF on demand.

Without MBC support, any attempt to run these larger games results in the emulator looping endlessly or crashing, because the bank-switching writes are silently ignored and the game never sees the code it expects to find in the upper window.

Cartridge Header Detection

Every Game Boy cartridge stores metadata in a fixed header at $0100–$014F. Three bytes are particularly important for the emulator:

  • $0147 — Cartridge Type: identifies which MBC chip (if any) is present, and whether the cartridge includes RAM, a battery, or an RTC.
  • $0148 — ROM Size: encodes the number of 16KB ROM banks as a power of two. Value 0x00 means 2 banks (32KB), 0x01 means 4 banks (64KB), 0x05 means 64 banks (1MB), and so on.
  • $0149 — RAM Size: encodes the number of 8KB external RAM banks.

On startup, load_rom() reads these bytes and configures the MBC state accordingly:

uint8_t cart_type = rom[ROM_HEADER_CART_TYPE];
uint8_t rom_size  = rom[ROM_HEADER_ROM_SIZE];
uint8_t ram_size  = rom[ROM_HEADER_RAM_SIZE];

switch (cart_type) {
    case 0x00: mbc.type = MBCType::None; break;           // ROM ONLY
    case 0x01: mbc.type = MBCType::MBC1; break;           // MBC1
    case 0x03: mbc.type = MBCType::MBC1; has_battery = true; break; // MBC1+RAM+BATTERY
    case 0x0F: mbc.type = MBCType::MBC3; has_rtc = true; has_battery = true; break;
    case 0x13: mbc.type = MBCType::MBC3; has_battery = true; break; // MBC3+RAM+BATTERY
    case 0x19: mbc.type = MBCType::MBC5; break;           // MBC5
    // ...
}

num_rom_banks = 2 << rom_size; // 0 → 2 banks, 1 → 4 banks, 2 → 8 banks, …

The computed num_rom_banks is used as a modulus whenever a bank number is applied, so out-of-range writes wrap correctly and never read past the end of the ROM buffer.

MBC1

MBC1 was the first memory bank controller Nintendo produced and is found on hundreds of early Game Boy titles. It supports up to 2MB of ROM (128 banks) and up to 32KB of external RAM (4 banks).

Register Map

MBC1 exposes four write-only registers, each mapped to a region of the normally read-only ROM area:

Address rangeFunction
$0000–$1FFFRAM enable — write 0x0A in the lower nibble to enable external RAM, any other value to disable
$2000–$3FFFROM bank number (lower 5 bits). Writing 0 is automatically promoted to 1
$4000–$5FFFRAM bank number / upper 2 bits of ROM bank number (2 bits)
$6000–$7FFFBanking mode: 0 = ROM banking (large ROM / small RAM), 1 = RAM banking (small ROM / large RAM)

Banking Mode

The two-bit value written to $4000–$5FFF plays a dual role depending on the active mode:

  • ROM banking mode (default): the bits form the upper 2 bits of the ROM bank number, giving a full 7-bit bank address (up to 128 banks / 2MB). External RAM is locked to bank 0.
  • RAM banking mode: the bits select which 8KB RAM bank is mapped to $A000–$BFFF. The ROM bank upper bits are forced to 0, limiting ROM to the first 512KB.

In ROM banking mode the bank 0 area ($0000–$3FFF) can also be remapped. When the upper 2 bits are non-zero, ROM bank 0 maps to the first bank of the selected 512KB section instead of the very first bank:

uint8_t Memory::read(uint16_t addr) const {
    // Bank 0 area — remapped in MBC1 RAM banking mode
    if (addr < ADDR_ROM_BANK0_END) {
        if (mbc.type == MBCType::MBC1 && mbc.banking_mode) {
            uint32_t bank = (mbc.ram_bank << 5) % num_rom_banks;
            return rom[bank * ROM_BANK_SIZE + addr];
        }
        return rom[addr]; // Fixed bank 0
    }

    // Switchable bank area
    if (addr < ADDR_VRAM_START) {
        uint32_t bank;
        if (mbc.type == MBCType::MBC1) {
            bank = ((mbc.ram_bank << 5) | mbc.rom_bank) % num_rom_banks;
        } else {
            bank = mbc.rom_bank % num_rom_banks;
        }
        return rom[bank * ROM_BANK_SIZE + (addr - ADDR_ROM_BANK0_END)];
    }
    // ...
}

Register Writes

// $2000–$3FFF: ROM bank (lower 5 bits)
case MBCType::MBC1:
    mbc.rom_bank = value & 0x1F;
    if (mbc.rom_bank == 0) mbc.rom_bank = 1; // bank 0 not selectable here
    break;

// $4000–$5FFF: upper bits / RAM bank
case MBCType::MBC1: mbc.ram_bank = value & 0x03; break;

// $6000–$7FFF: banking mode
case MBCType::MBC1: mbc.banking_mode = value & 0x01; break;

MBC2

MBC2 is a simpler variant found on a small number of early titles. Its key differences from MBC1 are:

  • Only 16 ROM banks (256KB maximum).
  • Built-in 512×4-bit RAM — half-byte (nibble) values only; the upper 4 bits of each byte always read back as 1.
  • The RAM enable and ROM bank registers share the address range $0000–$3FFF. Bit 8 of the write address distinguishes them: if bit 8 is clear, the write targets RAM enable; if bit 8 is set, it selects the ROM bank (lower 4 bits).
// RAM enable ($0000–$1FFF, bit 8 must be clear)
if (addr < MBC_RAM_ENABLE_END) {
    if (mbc.type == MBCType::MBC2 && (addr & 0x100)) return; // bit 8 set = ROM bank select area
    mbc.ram_enabled = (value & 0x0F) == 0x0A;
    return;
}

// ROM bank ($2000–$3FFF, bit 8 must be set for MBC2)
case MBCType::MBC2:
    if (addr & 0x100) {
        mbc.rom_bank = value & 0x0F;
        if (mbc.rom_bank == 0) mbc.rom_bank = 1;
    }
    break;

RAM reads and writes mask the address to 9 bits (addr & MBC2_RAM_MASK) to stay within the 512-byte space, and reads OR the result with 0xF0 to present undefined upper nibbles as ones.

MBC3

MBC3 extends MBC1's design with a 7-bit ROM bank number (no more skipped banks at 0x20/0x40/0x60) and an optional real-time clock. It is used by Pokémon Red, Blue, Gold, Silver, and Crystal, among others.

ROM Banking

Writing to $2000–$3FFF sets all 7 bits of the ROM bank number in one write, enabling up to 128 banks (2MB) without the awkward two-register scheme of MBC1:

case MBCType::MBC3:
    mbc.rom_bank = value & 0x7F;
    if (mbc.rom_bank == 0) mbc.rom_bank = 1;
    break;

RAM Bank and RTC Register Select

Writes to $4000–$5FFF select either an external RAM bank (values 0x00–0x03) or one of five RTC registers (values 0x08–0x0C). The same address window at $A000–$BFFF then reads or writes the selected target:

Value writtenSelected target
0x00–0x03External RAM bank 0–3
0x08RTC S — seconds (0–59)
0x09RTC M — minutes (0–59)
0x0ARTC H — hours (0–23)
0x0BRTC DL — day counter low byte
0x0CRTC DH — day counter high bit, halt flag, carry flag

RTC Latching

To read a consistent snapshot of the clock without it ticking mid-read, the game writes 0x00 then 0x01 to $6000–$7FFF. This latches the current RTC values into a separate buffer; subsequent reads from $A000–$BFFF return the latched copy until it is latched again:

case MBCType::MBC3:
    if (mbc.latch_reg == 0x00 && value == 0x01) {
        std::memcpy(mbc.rtc_latched, mbc.rtc, 5); // snapshot current time
    }
    mbc.latch_reg = value;
    break;

RTC Tick

The RTC advances independently of the CPU. Each call to tick_timers() forwards the elapsed cycles to MBC::tick_rtc(), which increments a cycle accumulator and cascades through seconds → minutes → hours → days when thresholds are crossed. The halt bit in RTC DH (bit 6) stops the clock when set:

void MBC::tick_rtc(int cycles) {
    if (type == MBCType::MBC3) {
        if (rtc[4] & 0x40) return; // halted
        rtc_cycles += cycles;
        if (rtc_cycles >= CPU_FREQUENCY) {   // one second at ~4.19 MHz
            rtc_cycles -= CPU_FREQUENCY;
            if (++rtc[0] == 60) {      // seconds
                rtc[0] = 0;
                if (++rtc[1] == 60) {  // minutes
                    rtc[1] = 0;
                    if (++rtc[2] == 24) { // hours
                        rtc[2] = 0;
                        uint16_t day = rtc[3] | ((rtc[4] & 0x01) << 8);
                        if (++day >= 512) {
                            day = 0;
                            rtc[4] |= 0x80; // day carry flag
                        }
                        rtc[3] = day & 0xFF;
                        rtc[4] = (rtc[4] & 0xFE) | ((day >> 8) & 0x01);
                    }
                }
            }
        }
    }
}

MBC5

MBC5 is found on most Game Boy Color titles and later Game Boy games. Its main advancement over MBC3 is support for up to 512 ROM banks (8MB) by spreading the bank number across two registers:

Address rangeFunction
$2000–$2FFFLow 8 bits of ROM bank number
$3000–$3FFFBit 8 (9th bit) of ROM bank number
$4000–$5FFFRAM bank number (4 bits, up to 16 banks)

Unlike MBC1 and MBC3, MBC5 allows selecting bank 0 in the switchable window, so there is no zero-bank promotion:

case MBCType::MBC5:
    if (addr < 0x3000) {
        mbc.rom_bank = (mbc.rom_bank & 0x100) | value;         // low 8 bits
    } else {
        mbc.rom_bank = (mbc.rom_bank & 0xFF) | ((value & 0x01) << 8); // bit 8
    }
    break;

Battery-Backed Save RAM

Cartridges marked with the battery flag in the header contain a small CR2016-style coin cell that keeps external RAM powered when the Game Boy is off. This is how games like Pokémon store player progress.

The emulator mirrors this by writing the contents of ext_ram to a .sav file (same name and directory as the ROM) when the emulator closes, and loading it back on startup.

RTC Persistence

For MBC3 cartridges with an RTC, simply restoring the five register bytes is not enough — the clock should reflect time that passed while the emulator was closed. To handle this, a Unix timestamp (int64_t) is written to the save file immediately after the RTC bytes. On load, the difference between the saved timestamp and the current time is computed and forwarded to advance_rtc(), which cascades the elapsed seconds through the full register chain:

void Memory::save_battery(const std::string& rom_path) {
    if (!has_battery || ext_ram.empty()) return;
    std::string save_path = /* replace extension with .sav */;
    FILE* file = fopen(save_path.c_str(), "wb");
    if (file) {
        fwrite(ext_ram.data(), 1, ext_ram.size(), file);
        if (has_rtc) {
            fwrite(mbc.rtc, 1, 5, file);
            int64_t now = static_cast<int64_t>(time(nullptr));
            fwrite(&now, sizeof(now), 1, file);
        }
        fclose(file);
    }
}

void Memory::load_battery(const std::string& rom_path) {
    if (!has_battery) return;
    std::string save_path = /* replace extension with .sav */;
    FILE* file = fopen(save_path.c_str(), "rb");
    if (file) {
        fread(ext_ram.data(), 1, ext_ram.size(), file);
        if (has_rtc && file_size >= (long)(ext_ram.size() + 5)) {
            fread(mbc.rtc, 1, 5, file);
            if (file_size >= (long)(ext_ram.size() + 5 + sizeof(int64_t))) {
                int64_t saved_time = 0;
                fread(&saved_time, sizeof(saved_time), 1, file);
                int64_t elapsed = static_cast<int64_t>(time(nullptr)) - saved_time;
                if (elapsed > 0)
                    mbc.advance_rtc(elapsed);
            }
        }
        fclose(file);
    }
}

void MBC::advance_rtc(int64_t seconds) {
    if (rtc[4] & 0x40) return; // RTC halted, don't advance
    int64_t s = rtc[0] + seconds;
    rtc[0] = s % 60;
    int64_t m = rtc[1] + s / 60;
    rtc[1] = m % 60;
    int64_t h = rtc[2] + m / 60;
    rtc[2] = h % 24;
    uint16_t day = rtc[3] | ((rtc[4] & 0x01) << 8);
    day += static_cast<uint16_t>(h / 24);
    if (day >= 512) { day %= 512; rtc[4] |= 0x80; } // day carry
    rtc[3] = day & 0xFF;
    rtc[4] = (rtc[4] & 0xFE) | ((day >> 8) & 0x01);
}

The halt flag in RTC DH is respected: if the game had halted the clock before saving, advance_rtc is a no-op. The save file format is compatible with other emulators (mGBA, BGB, etc.) that use the same convention of appending a Unix timestamp after the RTC bytes, so saves can be transferred between them.

MBCs Not Implemented

The Game Boy library includes a handful of other memory bank controllers beyond MBC1–5. None of them were implemented here because the games that use them are either extremely rare, region-specific, or require platform features (like IR blasters or motion sensors) that go well beyond basic emulation:

  • MBC6 — used by only a single game (Net de Get: Minigame @ 100, Japan only). It adds a flash ROM that the game could write to for downloadable minigames via the Game Boy Mobile Adapter. No game in the normal Western library uses it.
  • MBC7 — found exclusively in Kirby Tilt 'n' Tumble and Command Master. It includes a two-axis accelerometer (ADXL202) that the game uses for tilt controls. Proper emulation would require mapping tilt input to mouse or gyroscope input, which is outside the scope of this project.
  • HuC1 — an MBC1 variant used by Hudson Soft titles. It replaces the upper RAM bank register with an infrared transceiver control register. The games that use it (Pokémon Trading Card Game sequel, etc.) are uncommon.
  • HuC3 — another Hudson Soft controller with an RTC and IR port, found in Robopon Sun and a few other Japan-exclusive titles.
  • MMM01 — a multi-cart MBC used for compilation cartridges sold in some regions. Its bank mapping is more complex and it is not used by any standalone retail game.
  • Pocket Camera / GB Camera — contains a full CMOS image sensor and a custom controller chip. Emulating it accurately would require simulating camera input, which is a project of its own.
  • TAMA5 — found only in Tamagotchi (GB version). Has an unusual register interface and, like HuC3, includes an RTC.

Together, MBC1, MBC2, MBC3, and MBC5 cover the overwhelming majority of the Game Boy and Game Boy Color catalog. Skipping the controllers above means missing only a small number of obscure or Japan-exclusive titles, none of which were target games for this emulator.

What's Next

MBC support unlocks the vast majority of the Game Boy library. The remaining major systems still to implement are:

  1. Audio Processing Unit (APU): the Game Boy's four-channel sound system (pulse, wave, noise).
  2. Game Boy Color support: double-speed mode, extended palettes, and VRAM bank switching.
